# 任务 12.10：深化一个节日与地图小惊喜（负责：sol；Fable 验收）

## 背景

12.0b 调研（`docs/research/2026-11-15-content-expansion.md` §2、§4 E06、E12）发现两个问题：

- 节日只有当天的活动，事前没有准备，散场后也没有回访；
- 惊喜大多是弹窗，很少是"先在地图上看见异样，再走过去参与"。

12.1 的聚餐试点和 12.6 的公共花坛，已经验证了"邀请 → 共同做事 → 回访 → 留痕"这套写法。

## 要做的

1. **深化一个节日（E06）**：从现有五个节日里选一个，在报告里说明为什么选它。
   - **事前准备**：节日前一两个代表日，有一个准备行动，例如一起包饺子、扎彩带、做灯笼。准备有两种合理分支。
   - **当天**：结果按准备分支不同；保留一个小操作（菜单里的选择即可，不做反应小游戏）。
   - **散场后**：下一个代表日或下一季，有回访台词或一件留下的物品。
   - 两年玩下来不能完全一样，可以复用现有的结果轮换。
   - 下雨要有室内替代；没参加也不影响主线。
   - 新增状态写成契约，供 astra 做画面。
2. **地图小惊喜（E12）**：做约 3 个，改编自已有主题（寻猫、二手交换、遗落物件）。
   - 每个惊喜先作为一个地图上的异常出现，例如某个锚点上多了一样东西，或者某位镇民在不寻常的地方；玩家走过去才触发。
   - 有两种结果，各有收尾；留下一次回访或场景痕迹。
   - 错过就过期，不补发；固定种子能复现；读档后不会重复领取。
   - 在报告里写清楚：异常出现在哪个锚点、显示什么、持续多久。astra 会按这个画出来，本任务不改 `apps/web`。

## 约束

- 文案遵守 `style-guide.md`：中英同步，旁白用"你"。不涉及政策数字。
- 只改 `packages/game/**`，外加报告 `docs/tasks/reports/12.10-festival-and-surprises.md`。公开 API 的现有名字和形状不变，新增字段要向后兼容。
- 测试：
  - 节日的准备、当天、散场三段，两种分支，雨天，未参加；
  - 惊喜的出现、过期、两种结果、不重复领取、存读档；
  - 已有体量、平衡、好感剧情断言照旧要过；快进每年事件数不能下降。
- 验收命令：`pnpm lint && pnpm typecheck && pnpm test && pnpm build`，退出码须为 0。
- 不 commit，报告里按"应当成为的 commit"分组。不要过度工程化：不做通用事件编辑器，也不做惊喜调度框架。
