# 14.1 浏览器端自动回归：报告

执行者：Fable（Claude Opus 5.5）。用户 2026-11-16 要求"先不用 sol，直接你自己去做"。

## 1. 做了什么（按 commit 列）

1. `Fix: 游戏界面两处无障碍问题（axe serious）`
   - `apps/web/app/game/game-view.tsx`：天气图标的 `span` 带 `aria-label`，补上 `role="img"`，消除 `aria-prohibited-attr`。
   - `apps/web/app/game/game-client.tsx`：快进、结束当天两个按钮的 `aria-label` 改为与可见文字一致的短词（"快进季""结束当天"），完整说法留在 `title` 和隐藏文字中，消除 `label-content-name-mismatch`。
2. `Test: 新增 apps/e2e 浏览器回归并接入 CI，部署改为等 CI 通过`
   - 新增 `apps/e2e` 包，使用 `@playwright/test` 1.65.1 和 `@axe-core/playwright` 4.14.0，浏览器只用 Chromium。
     - `serve.ts`：用 Node 原生运行的极简静态服务，服务 `apps/web/out`。
     - `playwright.config.ts`：两个项目，desktop 为 1280×800，mobile 为 375×812 触屏；开启 `reducedMotion: reduce`。
   - `tests/` 下的用例，共 25 条：
     - `site.spec.ts`：首页 → 开始模拟 → 问卷第一步；一份已完成草稿的结果页显示两栏评估；`/policy`、`/about` 能打开。
     - `game.spec.ts`：
       - 选人页列出 4 位主角，4 位都能开局；
       - 家里菜单 → 和周沅聊天 → 关闭 → 实际寻路走到公园池塘；
       - 刷新后点"继续上次"能恢复；
       - 快进一季到季度小结，再进入第 2 季；
       - 钓鱼（简易模式，等到咬钩提示再收竿，最多 5 竿）；
       - 做饭：烤土豆逐步做完，沙拉直接跳过，两次都看到成品；
       - 在火车站离开英国 → 确认 → 结局页显示回忆区 → "在模拟器里打开这条时间线"跳到结果页。
     - `mobile.spec.ts`：选人页没有横向滚动；开局首屏能看到画布和 Dock；地点抽屉选地点后能走到；聊天框在屏内。
     - `a11y.spec.ts`：首页、问卷、政策页、说明页、选人页、结果页和运行中的游戏，都没有 serious 或 critical 级别的 axe 违规。
     - `helpers.ts`：开局、关闭开场卡、改写存档后继续、走到某地，以及共用的已完成问卷草稿。
   - 截图对比只选内容固定的 6 个画面：首页、问卷第一步、选人页、结局回忆区，以及手机选人页。游戏画布有天气和随机数，不做整屏比对。
   - 根 `package.json` 加 `pnpm e2e`；`pnpm test` 不变，本地 gate 不受影响。`.gitignore` 忽略 e2e 的结果目录。
   - `.github/workflows/ci.yml`：新增 `e2e` job（安装依赖 → 构建 → 安装 Chromium → `pnpm e2e`），失败时上传报告与截图差异。
   - `.github/workflows/deploy.yml`：改为 `workflow_run`，只有 main 上的 push 触发的 CI 全部成功（含 e2e）才部署，并按该次 CI 的 commit 检出。原来部署与 CI 是并行跑的，测试失败也照样上线。
   - `.github/workflows/e2e-baselines.yml`：手动触发，在 Linux 上跑 `--update-snapshots`，把截图目录作为 artifact 上传；下载后提交到 `apps/e2e/tests/__screenshots__`。
   - 截图基准图只认 CI 的 Linux 环境：本地默认不比对截图（`ignoreSnapshots`），设置 `E2E_SNAPSHOTS=1` 才开启比对。

## 2. 怎么验证的（命令 + 结果）

- `pnpm e2e` 本地连跑 3 次：25 passed、25 passed、25 passed，每次约 45 秒。
  - 中途发现钓鱼用例有一次失败，原因在测试本身：钓到杂物时"钓到了！"和杂物说明同时出现，定位命中两个元素。修正为只读 `role="status"` 的结果行后，单条连跑 8 次都通过。
- axe 首次跑出游戏界面的 2 个 serious 问题（见 commit 1），修复后通过。
- 全仓 `pnpm lint && pnpm typecheck && pnpm test && pnpm build`：GATE EXIT 0（policy-data 22、engine 2,577 + 1 跳过、game 1,315、web 481）。

## 3. 没做或没验证的

- CI 上的 e2e 首次运行时还没有 Linux 基准图，截图断言会失败，部署也会因此暂停一次。要先运行 `E2E screenshot baselines` 工作流，下载截图并提交，之后才会全绿。
- 中文界面以外只测了少量英文：所有用例都按中文文字定位。
- 没有覆盖：续签、菜地种收、节日、商店购买、收藏册、各地图惊喜。

## 4. 发现与建议

- 部署原先不等 CI，这是比缺少 e2e 更大的风险，本次已一并修正。
- 结局确认面板（"确认 / 再等等"）在可访问性树里不在 `dialog` 元素内，可以请 astra 检查结构是否合理。
- 后续可按需补用例：续签与签证中心、菜地、商店、节日，以及英文界面的一轮冒烟测试。
