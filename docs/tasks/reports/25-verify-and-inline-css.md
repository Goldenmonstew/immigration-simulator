## 2. 怎么验证的

- **节点回收。** 在正式站 7d3d0ce 上，用 Puppeteer 页面运行 Lighthouse 13.6.0，并包装 CDP 会话，记录内部 `DOM.resolveNode` 的返回。
  - 对照 6 次，LCP 节点都返回 `No node with given id found`。
  - 页面脚本保留横幅节点引用的 2 次都能取到，报告列出已脱离文档的 `div.townBanner`。
  - 回收事件和时点没有直接观察到。
- **分带宽。** 实际限速交替运行：
  - 屏蔽横幅与正常各 3 次：样式表早 35–75 ms 下完，FCP 早 37–86 ms；
  - 屏蔽首批 9 个 Next.js 包（`beacon.min.js` 照常）与正常各 2 次：横幅下载约 0.70 s，正常约 1.0 s。
- **内联效果。** 本地 brotli 静态服务器，两版交替运行 Lighthouse：
  - 实际限速，游戏页各 3 次、首页各 2 次：FCP 都提前约 0.8 s；游戏页 LCP 提前 0.14–0.27 s，首页提前约 0.2 s；
  - 模拟限速，游戏页各 3 次：FCP 0.75–0.76 → 0.60 s，LCP 看不出变化。
- **外观。** 7 个页面在手机 412 宽、桌面 1280 宽下截整页图：
  - 14 对截图两版逐字节相同；
  - 内联版从首页客户端跳转到其余 6 页，两种宽度共 12 对，截图也相同。
- **构建与测试。**
  - `pnpm lint && pnpm typecheck && pnpm test && pnpm build` 退出码 0，web 单测 491 条；
  - 构建日志列出 `✓ inlineCss`，`game.html` 含 1 个 `<style data-precedence>`、无样式表链接；
  - `pnpm e2e` 本地通过。本地默认不做截图断言，截图断言以 CI 的 e2e 结果为准。
- **离线缓存。** 新断网用例在未修复 `sw.js` 的内联构建上失败：等 15 s，service worker 仍没有接管页面。修复后通过。
  - 另用临时用例确认，断网对 service worker 自己发出的请求同样生效：未缓存的请求失败；`/policy` 由 service worker 返回，状态 200。

## 4. 发现与建议

- **重复的样式表下载。** 游戏客户端是 `next/dynamic` 动态包，它的 CSS 与页面 CSS 是同一个文件。已观察到动态包载入时，页面多了一个指向该文件的链接，而这个文件已以 `<style data-href>` 内联。没查是运行时哪段代码决定的。这次下载不在首次绘制和 LCP 之前，暂不处理。
- **主要的带宽竞争者是脚本。** 实际限速下，首批 10 个脚本（约 180 KiB）在和横幅分带宽。如果还要压 LCP，下一步该看哪些首批脚本可以推迟。
