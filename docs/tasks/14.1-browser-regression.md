## 要做的

1. **新建 `apps/e2e` 包**，归 sol 维护，不改 `apps/web` 的源码。
   - 用 `@playwright/test`，浏览器只装 Chromium。
   - 对 `apps/web/out` 的静态导出起一个本地静态服务；可以写一个很小的 node 脚本，不引入额外的服务包。
   - 根脚本加 `pnpm e2e`。`pnpm test` 保持不变，本地 gate 不受影响。
2. **关键流程**（桌面 1280×800）：
   - 问卷：首页 → 填一条最短的有效时间线 → 结果页出现两栏评估；`/policy`、`/about` 能正常打开。
   - 游戏：
     - 四位角色都能开局，并关掉开场卡；
     - 在家里打开菜单、和室友聊天、关闭；
     - 走到一个户外地点（等待真实寻路，不直接调用场景内部方法）；
     - 快进一季，到达季度小结；
     - 存档后刷新页面，点"继续上次"能恢复；
     - 用构造的存档进入结局页，看到回忆位。
   - 小游戏：用构造的存档，完成一次钓鱼（简易模式）和一次做饭（走步骤，也试一次跳过），看到成功卡。
3. **手机流程**（375×812，触屏）：开局后首屏能看到画布与底部 Dock；打开地点抽屉、选一个地点；对话框不溢出；页面没有横向滚动。
4. **截图对比**：
   - 对少量稳定的画面做 `toHaveScreenshot`：首页、选人页、季度小结、结局回忆区、手机首屏。
   - 用 `reducedMotion: 'reduce'`；固定存档和时间；屏蔽不确定的区域，例如画布里的动画、天气，用 mask 遮住。
   - 基准图要在与 CI 相同的 Linux 环境生成：提供一个 `workflow_dispatch` 工作流，在 CI 里生成或更新基准图并作为 artifact 上传，由 Fable 下载后提交。在报告里写清楚步骤。本地 macOS 生成的基准图不入库。
5. **无障碍检查**：用 `@axe-core/playwright` 检查首页、问卷第一步、结果页、选人页、游戏主界面，遇到 `serious` 或 `critical` 级别就失败。已存在的问题能修的写进报告交给 astra，不能修的明确列出临时豁免，不要静默忽略。
6. **CI**：
   - 在 `ci.yml` 里加一个 e2e job：先构建，再跑 `pnpm e2e`，失败时上传报告和截图差异作为 artifact；
   - 改 `deploy.yml`：只有 CI（含 e2e）在 main 上成功后才部署，用 `workflow_run` 或合并成一个工作流都可以，保持现有的 secrets 和变量名不变；
   - 在报告里给出 GitHub runner 上 e2e job 的预估或实测耗时。

## 约束

- 只改 `apps/e2e/**`、`.github/workflows/**`、根 `package.json` 的脚本与 `pnpm-lock.yaml`、`.gitignore`，外加报告 `docs/tasks/reports/14.1-browser-regression.md`。不改 `apps/web` 和 `packages/**`。如果发现 `apps/web` 缺少稳定的选择器或有 bug，写进报告交给 astra。
- 依赖版本固定。本机已缓存 Playwright 的 Chromium（`~/Library/Caches/ms-playwright/chromium-1223`），选择与它匹配的 `@playwright/test` 版本，或在报告里说明为什么不匹配。
- 测试要稳定：本地连跑 3 次都通过；不使用固定的 `sleep`，改为等待具体状态；不依赖网络。
- 验收命令：
  - `pnpm lint && pnpm typecheck && pnpm test && pnpm build`，退出码须为 0；
  - `pnpm e2e`，退出码须为 0（截图对比在本地可以只跑非截图部分，在报告里说明）。
- 不 commit，报告里按"应当成为的 commit"分组。不要过度工程化：不做页面对象层级体系，不做测试数据生成框架；构造存档的帮助函数放在一个文件里即可。
